# ALCG v0.32 — Prequential Forecast-Model Selection and Domain Boundaries

**Status:** exploratory finite experiment, dated 2026-11-11. UTF-8 canonical research source. This release extends the AI Language Creation Game (ALCG) without changing the previously published language grammar, symbol registry, finite causal fixtures or historical benchmark values.

## 1. Research question

When a prefix-only forecast of cache workloads becomes unreliable, can ALCG explicitly represent a bounded choice to **retain, switch or defer a forecasting model**, with evidence that existed at the time of the choice? This is not an evaluation of independent AI language comprehension. It is a transparent, symbolic and reproducible computation experiment.

v0.30 generated predictions from observed read and revision-change events. v0.31 froze predictions and scored them only against later completed event windows. v0.32 makes **the predictive model itself** a selectable object. It compares previously issued forecasts over a fixed number of closed windows, then records an ALCG `SELECT_V032(...)` expression.

## 2. Data, expert models and fixed conditions

There are four **synthetic** event sequences: `stable`, `churn`, `sparse` and `drift`. Each has 192 explicitly indexed read/idle opportunities, generated by the unchanged v0.30 deterministic generator. No event is an empirical user access or production sensor reading.

Forecast issue cuts are `32, 64, 96, 128, 160`. Each forecast concerns the *following* 32 opportunities. Each model sees the last 32 opportunities available at its issue cut; the `LAGGED` model can additionally use the previous completed 32-opportunity block, never the block it is now predicting.

| Expert | Fixed specification | Meaning |
|---|---|---|
| `RAW` | v0.30 smoothed read and reset probabilities, without additional lagged calibration | Baseline |
| `LAGGED` | v0.31 calibration using only the most recent **closed** evaluation block; defaults to `RAW` at the first cut | Delayed correction |
| `HEDGE` | Uses the RAW read probability and sets reset probability to `max(RAW reset probability, 1/3)` | Explicitly conservative reset hedge |

All probabilities are stored as exact rational pairs `{num, den}`. The `HEDGE` floor is a human-designed, fixed candidate, **not** a learned parameter. The expert inventory is closed for this release and cannot be amended from future data during an issuance.

At a cut with fewer than the v0.30 minimum observations, the decision is `DEFER`, with the previously safe `direct` read route. In the `sparse` stream this happens at all five cuts. Those cuts are **not** scored as successful model predictions.

## 3. Exact scoring and switch policy

For a completed interval, let `p` be the forecast probability of a read, `q` the forecast probability of a reset on a consecutive read pair. The empirical binary outcomes are retained per opportunity or gap. The two Brier components are:

$$
B_{read}(p)=\frac{1}{N}\sum_{i=1}^{N}(p-y_i)^2
$$

$$
B_{reset}(q)=\frac{1}{G}\sum_{j=1}^{G}(q-z_j)^2
$$

The reset component is omitted when the interval has no eligible read gaps. The **predeclared** combined loss is the sum of the available components; it is not a probabilistically derived optimal utility and should not be compared to an external benchmark with a different definition.

At an issue time, only the **last two already closed** intervals with successfully issued candidate forecasts may contribute to the comparison. For each expert, the arithmetic mean of its historical combined losses is computed using exact rational arithmetic. Changing away from the incumbent requires strictly exceeding an explicit fixed penalty of `1/10000`:

$$
L_{candidate}+\frac{1}{10000}<L_{incumbent}
$$

In a tie, or when improvement is insufficient, the incumbent is kept. If there is no completed evidence, the system initializes with `RAW`; if it has insufficient event observations to produce a valid forecast, the result is `DEFER` rather than a fabricated probability. A model switch does not by itself imply a change in the separate cache-versus-direct recommendation.

For transparency, each issue contains its prefix fingerprint, source receipt, all three model predictions, previously closed evaluation receipts, losses, selected expert and separate cache route. The issuance digest covers the complete issue payload. A settlement is created only after its future block has actually closed and has its own receipt. The issue and its settlement are never collapsed into one backdated prediction.

## 4. Fixed results — synthetic, not production

The deterministic v0.32 experiment generated **20** issuance windows across four sequences. **15** have enough data for candidate scores, and **five** are explicitly deferred. There were **five** past-evidence-based switches:

| Scenario | Cut | Selected expert after the switch |
|---|---:|---|
| stable | 96 | LAGGED |
| churn | 64 | HEDGE |
| churn | 96 | LAGGED |
| drift | 96 | HEDGE |
| drift | 160 | LAGGED |

Against the **same 15 eligible later windows**, mean combined Brier loss is:

| Policy | Mean combined Brier loss (rounded) |
|---|---:|
| Dynamic v0.32 switching | 0.208214 |
| Always RAW | 0.216724 |
| Always LAGGED | **0.204886** |
| Always HEDGE | 0.244737 |

This is an intentionally mixed result. Dynamic switching improves over `RAW` on the selected fixtures but **does not beat the best constant expert (`LAGGED`) on those same fixtures**. An oracle allowed to pick the lowest-loss model separately after seeing each future result would do better still, but is **not a deployable forecast policy**. Thus the experiment establishes a repeatable model-switching mechanism and its limitations, **not universal improvement**.

`reports/model-selection-v0.32.json` stores all exact rational results, hashes, issued expert forecasts, completed observations, loss decomposition, routes, switch evidence and these summary statistics. Floating-point numbers in this note are display-only approximations; computation uses the exact ratios in the JSON report.

## 5. AI-readable trace syntax

An example trace:

```text
SELECT_V032(scenario=DRIFT, at="128", selected=HEDGE, reason=KEEP_INCUMBENT_UNDER_SWITCH_PENALTY, route=DIRECT, closed="2", prefix_sha256="...", issuance_sha256="...")
```

The ellipses are explanatory placeholders here; published samples contain full SHA-256 values. The samples have **20** lines of valid ALCG expressions in `samples/model-selections-v0.32.alcg`. The operator is an experimental documentary label, not an executable new grammar primitive or a claim of independently verified AI semantics. The Python verifier replays the corresponding **full** report issuance, rather than trusting the displayed label alone.

## 6. Validation and invariants

- Time causality: issuing at cut `t` uses only event flags at logical ticks before `t`. A forecast is valid when supplied **only** with that prefix, even when the future is unavailable.
- Historical comparison: a score enters a decision only once that earlier interval has ended, and no more than two completed windows are used.
- Evidence separation: a forecast issue hash and its later settlement hash are distinct; an issue cannot be reconstructed from future outcomes while pretending to be earlier.
- Replay: each sealed report record can be recomputed from the named deterministic source and its exact fixed dependencies.
- Source integrity: changes to the pinned v0.30 fixture, v0.31 scoring report or v0.28 timing report invalidate the v0.32 policy configuration.
- Ambiguity: missing observations lead to `DEFER`, not forced selection; changing a role, outcome, expert or fingerprint causes a mismatch.
- Non-claims: receipts are integrity checks, not authentication; synthetic evidence is not a substitute for production statistics; passing unit tests is not independent AI comprehension.

## 7. Commands

Run from the repository root, using Python 3.10+ and its standard library:

```bash
python model_selection.py check
python model_selection.py report
python model_selection.py issue --case drift --at 128
python model_selection.py replay --case churn --at 96
python alcg.py check samples/model-selections-v0.32.alcg
python -m unittest discover -s tests -p 'test_model_selection.py' -v
```

GitHub Actions executes the standalone test plus the existing isolated full-suite runner, and checks the pinned JSON and 20 ALCG traces. No external AI API, proprietary data or paid model is used.

## 8. Scope and subsequent research

The stream generator, candidates, metric, lookback, thresholds, evaluation schedules and test domains are authored and fixed, so the results demonstrate an interpretable **finite model-selection protocol**, not a general learning theorem. v0.32 is primarily about how ALCG preserves temporal evidence and records a model-selection decision. A later experiment might vary the family of candidate models, use truly held-out event processes, and assess different decision losses, but these are not claims made by the present release.

**A symbolically readable model change is a claim about the evidence available *then*, not permission to rewrite the evidence known *later*.**
